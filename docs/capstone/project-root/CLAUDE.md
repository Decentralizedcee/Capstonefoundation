# Capstone Foundation: Website Project

A Christian charity helping widows and orphans in Enugu and Abuja, Nigeria. Simple, beautiful, fast, mobile-first, static website. Published first on Render at a temporary address; the domain `capstonefoundation.net` is connected later.

## 0. Source of truth and precedence

1. **`docs/capstone-build-spec.pdf`** is the full build specification. It is **canonical for all copy, content, routes, design tokens and acceptance criteria.** Read it fully before doing anything. Use the page copy **word for word**.
2. **This file** adds project conventions and resolves the few conflicts found when the spec was cross-checked (section 9). If this file and the spec disagree on copy or design, **the spec wins**, except where section 9 says otherwise.
3. **`docs/cross-check.md`** lists open decisions for the owner. Do not decide those yourself.
4. If something is not covered anywhere, **ask the owner before adding it.**

## 1. Ground rules (from the spec)

- Use only facts in the spec. **Never invent** statistics, names, dates, addresses, quotes, testimonials, partners or Scripture. Missing information uses the placeholder system (`src/config/site.ts` flags: `showFounding`, `showTrustees`, `showRegistration`, `showAddress`, `bankDetails`, `sportProgramUrl`; sections depending on a missing item stay hidden with a TODO comment).
- **Voice:** inspirational, hopeful, openly Christian. Short sentences, plain words. Always "we", never "the foundation says". Scripture is an invitation, not a hammer.
- **Privacy:** never publish money amounts, receipts, bank screenshots, diagnoses, case details or children's surnames. Young people appear by first name only. People appear in photos only with consent.
- **Do not build** the payment back end, database, user accounts or payment gateway. Prepare for them only as the spec describes (a `server/` folder with a README, and the `DonationPanel` component reading `PUBLIC_API_URL`).
- Never put a secret in the repository or the browser.

## 4. Environment variables

| Variable | Value now | Notes |
|---|---|---|
| `PUBLIC_SITE_URL` | the onrender.com address | Used for canonical links, sitemap, Open Graph, JSON-LD. Switch to `https://capstonefoundation.net` later. |
| `PUBLIC_INDEXABLE` | `false` | While false: every page gets `noindex` and `robots.txt` disallows everything. |
| `PUBLIC_API_URL` | empty | While empty, `DonationPanel` shows the bank-details card. |
| `UNSPLASH_ACCESS_KEY` | owner fills in `.env` | Local script only. Never in the browser or the repository. Access Key only, never the Secret Key. |

`PUBLIC_*` values are baked in **at build time**. After changing one (for example `PUBLIC_INDEXABLE` to `true`), **trigger a redeploy** on Render.

## 5. SEO rules for this site

- Titles and headings naturally include "Nigeria", "Enugu" or "Abuja". Other organisations use the name Capstone Foundation, so location must always be clear.
- Unique title and meta description per page, canonical URLs, Open Graph and Twitter tags, `sitemap.xml`, `robots.txt`, RSS for stories, JSON-LD `Organization` (name, logo, contact, `sameAs`) on every page.
- Lighthouse **95 or higher on mobile** for performance, accessibility, best practices and SEO, checked on the built site.
- **The SEO method (`docs/seo-step-by-step-guide.pdf`) applies here through the `blog` skill only:** stories are the topical-authority engine. There are no service + city pages. Do not run `service-page`.
- Do **not** submit to Search Console or request indexing until the real domain is live and `PUBLIC_INDEXABLE` is `true`.

## 6. Images

Order of preference: (1) the owner's own photos from `images-incoming/`; (2) Unsplash, **only for atmosphere images with no people** (landscape, sunrise, open Bible, fabric, bread, a building); (3) a flat `#EBEBEB` "Photo to come" placeholder.

- **Never** use Unsplash to show widows, orphans, teenagers or any scene that could pass as Capstone's own work.
- Unsplash use: key only in a local script (`scripts/fetch-unsplash.mjs`); use the URLs the API returns; trigger the download endpoint when a photo is chosen; credit the photographer and Unsplash with links (footer "Photo credits" line **and** next to the image).
- The pipeline (`scripts/process-images.mjs`) skips and reports receipts, bank screenshots, IDs, chat screenshots, medical documents, school-fee slips and anything showing an account number. Alt text describes only what is visible. No names unless the owner gives them. No videos in the repository.
- Propose a **slot map** (home hero, About, one per program page, Get involved) and **wait for approval** before placing any image.

## 7. Scripture

Quote only the verses in the spec (Psalm 68:5, James 1:27). For any other verse (stories about widows and orphans will want them) write the passage reference and add `TODO(owner): verify the verse text and name the translation`. Never paraphrase a verse as if it were a quotation.

## 8. Working method (gates)

1. **Stage 1: folders.** Check the environment, create the folder tree, verify it, then **stop** so the owner can add logos and photos.
2. **Stage 2: check uploads.** List what arrived; flag problems; do not process yet.
3. **Stage 3: plan.** Reply with the file tree, the component list and questions. **Wait for approval.**
4. **Stage 4: build,** in the spec's order: scaffold and config; design tokens and layout; Home; About; Programs; Get involved; Donate and Contact; Stories; SEO and structured data; final checks. After each step run the build and report in two or three sentences what is done and what is next. Stop at the slot map.
5. **Stage 5: acceptance** against the spec's "Done means" list.
6. **Stage 6: SEO skill.** Only when the owner says so.

The owner is not technical. Explain each step in plain words before doing it. Never ask the owner to paste a key into the chat.

## 9. Conflicts found in the spec, and how they are resolved

| # | Conflict | Resolution (owner to confirm) |
|---|---|---|
| 1 | The spec asks for optimised images through `astro:assets` **and** to use Unsplash's returned URLs (Unsplash requires hotlinking; Astro's remote-image optimisation re-hosts the photo). | Own photos go through `astro:assets`. Unsplash photos are hotlinked with a plain `<img>` and the API's URLs plus size parameters, with explicit width and height. |
| 2 | The `DonationPanel` component is described but missing from the component list. | It is built (reads `PUBLIC_API_URL`; shows the bank-details card while empty). |
| 3 | Unsplash credit is required "in the footer" only. | Footer "Photo credits" line **and** a credit beside each Unsplash image. |
| 4 | Testimonial 2 describes a healing from leg pain, while the privacy rule bans diagnoses and case details. | Used as written because the spec says she consented. **Owner to confirm** it is acceptable. See `docs/cross-check.md`. |
| 5 | Testimonial 1 shows the mother's surname alongside the child's first name, while the rule says children's surnames are never published. | Used as written because she agreed to be quoted. **Owner to confirm** (the surname effectively names the child's family). |
| 6 | The SEO skill expects a keyword list with volume and difficulty. The spec has none. | `keywords.csv` is seeded from the 8 story titles with **unverified** keyword guesses. Volumes and difficulty must be filled from Semrush before the skill relies on them. |
| 7 | Seeded stories are `draft: true` stubs, and the spec says not to publish drafts, while the `blog` skill publishes. | The skill writes new or filled posts with `draft: true`. The owner reviews and flips it. |
